# vPet Hub Implementation Plan

Approved scope: catalog, animated previews and local definition import, without accounts or store.

Architecture: a loopback-only Python HTTP server serves a static HTML/CSS/JS client.
The host reuses F1 PetDefinition validation. Imported definitions stay in memory;
no assets, saves, firmware or board contents are written. Installation remains disabled.

- [x] Test catalog, definition validation, rejected malformed/oversized payloads and restricted resource lookup.
- [x] Implement scripts/hub_server.py with GET catalog, PNG previews and POST definition validation.
- [x] Implement web/hub with catalog, stage/action selection, import and device capability state.
- [x] Run focused Python tests and browser desktop/mobile checks.
- [x] Document usage, validation boundaries and missing USB installer.

Evidence: 8 Hub tests plus 34 F1 tests pass. Chromium checks 1280px/390px,
five stages, nonblank canvas, valid/invalid import, disabled USB and no horizontal
overflow or JS errors. Screenshots inspected in out/hub-1280.png and hub-390.png.
No board connection, firmware modification, flash or publication performed.
Full Python tree: 1718 passed, 12617 existing warnings, 277.69 s.

Validation accepts an internal F1 JSON definition, not a signed vpetpack.
It cannot certify missing assets, publisher identity, board space or installability.
The USB button reports browser support only; no serial port is opened in this revision.
